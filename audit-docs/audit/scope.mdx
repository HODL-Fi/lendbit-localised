## Out of scope

- `contracts/mocks/*` — test doubles, never deployed.
- Third-party dependencies used unmodified: OpenZeppelin v5.5.0, Chainlink v0.3.2, forge-std v1.12.0. How the in-scope code **uses** them is in scope.
- Deployment scripts (`scripts/`) — configuration correctness matters operationally but script code is not a contract surface.
- Anything listed in [Known issues](/audit/known-issues) — accepted risks and design decisions, re-reports will be closed as known.

## Suggested review order

<Steps>
  <Step title="Storage and vault model">
    `LibAppStorage`, `TokenVault` — understand the two accounting domains before anything else.
  </Step>
  <Step title="Money flows">
    `LibProtocol` (borrow/repay/loans), `LibVaultManager` (deposit/withdraw), tracing every diamond ↔ vault boundary crossing.
  </Step>
  <Step title="Liquidation and pricing">
    `LibLiquidation` + `LibPriceOracle` — conversion math, rounding, staleness, bonus application.
  </Step>
  <Step title="Yield layer">
    `LibYieldStrategy` — index accounting, external Aave failure modes, rebalance-on-liquidation.
  </Step>
  <Step title="Admin and upgrade surface">
    `SecurityBase`, `LibDiamond`, vault upgrade path, parameter setters and their invariants.
  </Step>
</Steps>
